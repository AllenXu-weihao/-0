## 判读时分开的计数

一次运行同时记下这些数。它们问的是不同的事，后续判断要按列读，不能拿候选误码代替硬判差，也不能拿硬判差代替饱和。

| 名字 | 和谁比 | 问的是什么 |
|---|---|---|
| float 误码 | float 硬比特对发射真值 | 双精度检测器在这组信道上错了多少 bit。本批合计 256，其中 0 dB 为 190 |
| fixed_mvm 误码 | 现有定点矩阵口对发射真值 | 只量化 A2/A13/A5 三个矩阵口时，对真值错多少 bit。本批合计 254，少的 2 bit 在 0 dB |
| 候选误码 | 本档量化结果对发射真值 | 只把当前这一个数收窄之后，对真值错多少 bit。会随档变化，有时比 256 少，有时比 256 多 |
| 硬判差 disagreement | 本档硬比特对 float 硬比特 | 收窄这一个数之后，24 个判决里有几个离开了双精度算法。80 帧加总 |
| 饱和 saturation | 不和任何人比判决 | 这一个数在量化时有多少次被夹到该位宽的最大或最小可表示值 |

硬判差为 0 表示这 1920 bit 的 0/1 还和 double 算法一样。它不表示对真值的误码变好了。`A2_x` 在 S16.10：候选误码 253，硬判差 3，饱和 6。候选比 float 少错 3 bit，同时有 3 bit 和 float 不同。这 3 bit 是算法被改写了，只是改写的方向碰巧更接近发射比特。后续要保的是双精度算法，看硬判差，不看候选误码是否变小。

饱和是这个数自己的动态范围。有符号格式 S W.F 能表示的整数范围是 \([-2^{W-1},\,2^{W-1}-1]\)，再除以 \(2^F\)。超出就夹到端点，饱和次数加一。夹过之后，后面的计算用的是端点，不再是原来的 double 值。

严格 clean 同时要求两件：硬判差为 0，并且该边饱和为 0。只满足硬判差为 0，判决在这 80 帧上没动，数已经被夹过，动态范围没有余量。这种档写入下面的「硬判未动、已经饱和」，不写入 clean 列，也不作为协同实验的起点。

`observation.md` 生成时把 ERROR 行丢掉了，于是 `input_nv`、`input_iv` 被写成「梯子最窄档仍未翻硬判」。那是错的。S10.8 及更窄的噪声方差、S10.4 及更窄的脉冲方差没有硬判差，因为程序在方差不再为正时中断，没有产生判决。文件头已加更正。

## 实验目的

- 问题：FPGA / 数字 IC 要在双精度算法上把每个参与计算的数单独压到多窄，硬判还和 double 一致，该边还不饱和。
- 阶段 / 运算类型 / 量化点：F、I1、I2、I3、I4、R 六段；K1–K7 里已经插桩的 46 个边界。每次一个边界。
- 本次改变：该边界的总位宽 W 与小数位 F。有符号，MATLAB `round`（.5 远离零），饱和到 \([-2^{W-1},\,2^{W-1}-1]\) 再除回小数。实部、虚部分开。
- 保持不变：其余边界为 double；分组、3 轮、码本、`runtime.rate = 0.3`、候选数 9、端口数 20；不改算法，不建 LUT，不改求解器内部。
- 下游：每个格式都从原始 y、H 重跑前端，并跑完全部反馈轮。
- 验收：未设 BER / BLER 阈值，不设置信水平。硬判差按与 float 硬比特的不一致个数计，饱和按该边量化命中次数计。0 硬判差且 0 饱和只说明这 1920 bit 上该边没有把判决推开，也没有顶到端点。

## 计算过程：每次只改一个数

一帧先做前端，核内 I1–I4 重复 3 轮，末轮才读出 24 个 LLR。端口、分组和轮数来自 `deployment.mat`：20 端口 = 5 组 × 4 变量，候选 9，分组（置换后的天线槽，0 起）为 `[0,1,2] / [3,4] / [5] / [6] / [7]`。

```mermaid
flowchart LR
  F["F 锁存 H/y，Gram 与求解，Top9，写出 local"] --> I1["I1 A2，减峰，20 口稳定排序"]
  I1 --> I2["I2 softmax，均值方差，残差，mix，写出 λ 和 ai"]
  I2 --> I3["I3 A13，反排，阻尼，交换 β"]
  I3 --> I4["I4 A5，写出 36 个 z"]
  I4 -->|下一轮的旧 β| I1
  I4 -->|第 3 轮| R["R 两侧最大相减，夹到 ±20"]
```

I1 把每个口的 9 个候选做成稳定降序，后面的 exp、概率、λ 用这个名次。I3 按排序索引散回自然顺序，再和旧 β 阻尼。A2、A13、A5 的 9 条候选车道在矩阵里不相交。A13 的 ai 区只有每口第 1 列（logsumexp 的那一个标量）接到权重上，另外 160 个数是结构零。

控制变量落在这六段上：一张表里的一行就是一个被单独量化的数。同类运算可以共用算术说法，参数仍然按这个数自己的 W、F 记。K1 是三块实稀疏乘加；K2 是 Gram、右端、均值和方差这类复乘与归约；K3 的 4×4 求解这一轮没有在分解内部插桩；K4 是 exp 和 mix；K5 是排序和 Top9 的分数；K6 是减峰、阻尼和 LLR；K7 的地址与 valid 没有做近似压缩。

| 阶段 | 进入 → 完成 | 本批单独改过的数 |
|---|---|---|
| F 候选准备 | 完整 y、H、两个方差有效 → 候选、local、分组冻结 | `input_y` `input_H` `input_nv` `input_iv`；`frontend_gram` `frontend_rhs` `frontend_center` `frontend_cov` `frontend_variance` `frontend_score` `frontend_local` |
| I1 先验与排序 | 旧 β 与 local 有效 → α 和排序索引有效 | `A2_x` `A2_w` `A2_product` `A2_acc` `A2_out` `alpha` |
| I2 统计与证据 | 组内 4 口的 α 齐 → λ、ai 有效 | `exp` `sum_exp` `prob` `mu` `var` `residual` `weighted` `mix_a` `mix_b` `mix_output` `lambda` `ai` |
| I3 消息与阻尼 | λ、ai 齐 → 新 β 写完并交换 bank | `A13_x` `A13_w` `A13_product` `A13_acc` `A13_out` `raw` `rate` `damp_product_old` `damp_product_new` `damp_sum` `beta` |
| I4 后验 | 新 β 有效 → 36 个 z 有效 | `A5_x` `A5_w` `A5_product` `A5_acc` `A5_out` |
| R 软比特 | 末轮 z 有效 → 24 个 LLR | `llr` |

非末轮的 z 不回到下一轮。求解用到的 Gram 和右端量化了，`A\b` 内部仍是 double。

## 实验方法与复现

- MATLAB 25.2.0.2998904（R2025b）。工作目录为 `MIMO_v2_matlab (1)`。命令：`matlab -sd . -batch "addpath(fullfile(pwd,'experiments')); run_width_push();"`。约 7 分钟。
- 哈希见 `experiments/SOURCE_SHA256.txt`：`MIMO.m` 为 `83371d309eec814813a118a00666b01d0fb28ab33723dcd6c005d21cff31ce9d`，`deployment.mat` 为 `c6f359f279328c7bce5a854e46e7337004f802ad4344b1560943ac02661b754f`。
- 输入：`make_cases(20,1105)`，80 帧，每帧 24 bit。背景 SNR 0 / 10 / 20 / 30 dB 各 20 帧。归一化瑞利 `H/sqrt(8)`，64-QAM，`nv = 10^(-snr/10)`，脉冲额外方差 `25·nv`，每根接收天线以 ε = 0.05 进入脉冲分量。真值只用于数误码。输入里的 H 同时作为信道和接收端信道，本批没有 CSI 误差，也不是卫星信道。
- 两条基线每帧都重算：原始 `MIMO(...,'float')` 与 `fixed_mvm`。`fixed_mvm` 只量化三块矩阵口，用来对照，不用来解释某一个软统计边界。
- 乘积或累加被打开时，该矩阵改为按列、按非零行号顺序累加；只有被打开的那一级真正量化。全宽有序乘加相对 double 的最大 LLR 差：A2 为 3.81×10⁻⁸，A13 为 4.38×10⁻⁸，A5 为 5.39×10⁻⁸。这是 double 算完再量化，不是位精确整数 MAC。
- 消息类阶梯是 `24.12, 16.10, 12.8, 10.6, 8.4, 6.3, 4.2`。22、20、18 位不在这条阶梯里。
- 每个格式一个目录，内有 `per_frame.csv`、`summary.csv`、`report.md`。方差不再为正记为 ERROR，目录名带 `_ERROR`，不把该档写成 0 硬判差。

## 结论

本批状态是证据不足。80 帧上的单边对齐，允许作为下一次「一段内部一起压」的起点，不允许冻结 HDL，也不允许把 46 个起点收成一份位宽规格。

可以带进协同实验的起点，只限上表严格 clean 的那一档。A2 输出的阶梯起点是 S24.12。冒烟里的 S20.12 单独存放，要当成起点必须再跑一档确认，不能从阶梯表里直接取。mix 三个数和 `input_H` 没有 clean 起点。`input_nv`、`input_iv` 停在最后一个仍为正的格式；更窄是 ERROR，没有「未翻转」的结论。硬判差为 0 但仍饱和的档，包括 `A13_out` S16.10、`A5_out` S16.10、`A5_x` S12.8，不进入起点。`ai` 全位宽硬判差为 0，饱和落在未连接槽上，整列不进入起点。

## 分析

误差顺着数据流走，不按边界名字相加。

- 权重先于消息变短。A2 / A13 / A5 的系数在 S12.10 / S14.12 / S10.8 仍对齐，输入和输出在 S16.10 已经饱和或翻比特。协同压 I1、I3、I4 时，消息口会先于权重成为限制。
- 乘积和累加从 S42.26 / S45.26 收到 S20.12 时，这 80 帧上硬判和饱和都还干净，全宽有序乘加的 LLR 差在 10⁻⁸ 量级。这个模型是 double 累加后再量化。整数 MAC 的保护位要另做一次逐步溢出检查，才能把累加器从 S45.26 改到 RTL。
- I2 的短格式会在中等 SNR 翻比特：方差 S6.4、加权能量 S8.6、均值 S10.6。它们和残差、λ 串在同一条似然上，单边能短不等于一起短还成立。
- mix 在 8 个小数位上翻比特，整数位从 24 收到 16 以前结果不变。下一步是加小数位，而不是再砍总位宽。
- H 在 S24.12 就和 double 差 5 bit，全在 0 dB，饱和为 0。前端 Gram 在 S16.8 有 1 bit 落在 10 dB。候选集合一旦改了，后面三轮都在新的 9 个点上转。
- A5 输出和 A5 累加在 S12.8 共享 10 dB、20 dB 的那两帧。后验收窄时先看这两帧，不要只看 0 dB 的误码个数。
- 位宽影响不是单调的。`A2_x` 在 S6.3 硬判差 113，S4.2 为 97。`frontend_cov` 在 S16.8 最大 LLR 差 18.97、硬判差 2，S12.6 最大 LLR 差 0.496、硬判差 16。协同实验不用二分搜索。
- 30 dB 的 float 误码是 0。很窄的 A5 输出、y、H 和 Gram 会在这一档翻比特。协同组合只要在 30 dB 出现硬判差，就不再往下压。
