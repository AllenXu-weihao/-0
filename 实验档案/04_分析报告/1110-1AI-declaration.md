## 第二段：7–8 bit 覆盖

### 操作

1. 用 E0 的 `range.csv` 和 `hist.csv` 算非零样本占比。系数矩阵只计非零元 900、828、216，不把结构零算进分母。分母 2,383,381。
2. 每根线的小数位取「仍能包住该峰值的最细一档」。装不进有符号最大值的线保持双精度。8 bit 最大 127，7 bit 最大 63。
3. 新增 `experiments\run_share78.m`。输入仍是上面那份归档 `inputs.mat`。乘积或累加器格式一出现，矩阵乘走有序乘积累加再舍入。
4. 第一次 `run_share78` 在 peak8 第 61 帧（30 dB）停止：S8.6 把 `input_nv = 0.001` 收成 0，前端 `nv>0` 失败。该次 run 标成 ERROR。
5. 第二次把 `input_nv` 和 `input_iv` 留在双精度，80 帧的 peak8 和 peak7 都跑完。

临时脚本 `experiments\_share78.py`、`experiments\_flush78.py` 仍在磁盘上，只用于算占比和检查舍入到 0，不是实验结果。

### 结果

峰值能放进 8 bit 的非零样本占 96.3%。`mix_a` 峰值 925、`frontend_score` 峰值 391，留在双精度。7 bit 只能放进 77.7%，因为 `alpha`、`A2_out`、`A2_acc`、`A5_out`、`A5_acc`、`A13_x`、`ai` 的峰值在 114 到 124。`input_nv`、`input_iv` 各 80 个数，留在双精度，不改变这个比例。

双精度误码 256，分档 190 / 61 / 5 / 0。

|格式|候选误码|0/10/20/30 dB|硬判差|对变错 / 错变对|LLR 最大差|饱和|
|---|---:|---|---:|---|---:|---:|
|peak8|272|189 / 75 / 8 / 0|230|123 / 107|18.52|1|
|peak7|297|191 / 80 / 21 / 5|237|139 / 98|35|6|

peak8 在 30 dB 的 480 bit 硬判差是 0，该档 LLR 仍最大移动 6。peak7 在 30 dB 多出 5 个双精度没有的错。

### 分析

8 bit 按峰值留小数位之后，大峰值的线小数位是 0，`alpha` 和对应累加、输出的步进是 1。范围装得下，所以饱和只有 1 次；硬判差 230 来自步进，不是来自把峰值削掉。10 dB 错数从 61 增到 75，20 dB 从 5 增到 8。

7 bit 在不饱和的前提下到不了 85%。只量化峰值不超过 63 的线，30 dB 已经出现新的错。

30 dB 噪声方差 0.001 比 S8.6 的半个步进 1/128 还小，会被收成 0。这是第一次运行停住的原因，也说明一根 8 bit 线不能同时保住峰值 1 和 0.001。

判断是证据不足。没有冻结 7 bit 或 8 bit。小数位用的是这 80 帧自己的峰值。阻尼仍是运行时 0.3，不是 307/717。
